SEÇÃO 2 — CONCEITO DO PROJETO

2.1 Nome do Projeto: MetaMuseu — Galeria de Arte Virtual

2.2 Contexto e Objetivo no Metaverso:
Criar um ambiente educacional e cultural imersivo no contexto do Metaverso, simulando uma
galeria de arte virtual onde usuários podem visitar obras de arte digitais e explorar o
espaço como se estivessem em um museu físico. O objetivo é demonstrar como o Metaverso
pode democratizar o acesso à cultura e à arte, eliminando barreiras geográficas e financeiras.

2.3 Descrição Geral do Ambiente Virtual:
Uma galeria de arte retangular com piso claro, teto branco e paredes bege. O espaço é
dividido em ante-sala e salão principal. Na ante-sala, o visitante encontra o Validador de
Ingresso — um totem com botão azul que libera o acesso ao salão. No salão principal, 6
obras de arte (quadros com moldura dourada, cada um com cor única) estão distribuídas nas
paredes Norte, Leste e Oeste. A iluminação é quente (luz direcional com tom âmbar suave),
com lightmaps baked pelo Progressive CPU Lightmapper.

SEÇÃO 3 — CONFIGURAÇÃO TÉCNICA DO PROJETO

3.1 Versão do Unity e Porquê:
Unity 6000.3.14f1 (Unity 6 LTS), por ser a versão estável com suporte de longo prazo
recomendada para Meta XR SDK v60+ e ter suporte nativo ao URP 17.

3.2 Instalação do Meta XR SDK (Passo a Passo):
1. Window → Package Manager → "+" → Add package by name
2. Adicionado o escopo "com.meta.xr" no scopedRegistry do manifest.json apontando para
   https://npm.developer.oculus.com
3. Pacotes instalados:
   - com.meta.xr.sdk.core (v201.0.0)
   - com.meta.xr.sdk.interaction (v201.0.0)
   - com.meta.xr.sdk.interaction.ovr (v201.0.0)
4. XR Interaction Toolkit (v3.0.7) instalado pelo Package Manager oficial do Unity

3.3 Configurações de Build para Android/Meta Quest:
- File → Build Settings → Switch Platform → Android
- Texture Compression: ASTC
- Minimum API Level: Android 10 (API Level 29) — compatibilidade com Quest 2/3
- Target API Level: Android 12 (API Level 31)
- Scripting Backend: IL2CPP
- Target Architectures: ARM64 (único suportado pelo Quest)
- Player Settings → Company Name: FilipeMazon | Product Name: MetaMuseu

3.4 Configuração do XR Plugin Management:
- Edit → Project Settings → XR Plugin Management
- Aba PC (Windows): marcado OpenXR + Meta Quest feature group
- Aba Android: marcado OpenXR + Meta Quest feature group
- Interaction Profile adicionado: Oculus Touch Controller Profile

3.5 Movimentação no PC (Editor):
Utilizado o sistema de movimentação via CharacterController no PlayerController.cs —
o objeto XROrigin (tag: Player) é movido por WASD/setas no teclado. Para simular XR no
Editor (Linux): Window → Package Manager → XR Interaction Toolkit → Samples →
XR Device Simulator → Import; em seguida adicionar o prefab XR Device Simulator na cena.
O Meta XR Simulator não está disponível no Linux.

SEÇÃO 6 — SISTEMA DE INTERAÇÃO

6.1 Descrição da Interação Principal:
A única interação disponível no MetaMuseu é o Validador de Ingresso na ante-sala.
O visitante se aproxima do totem e pressiona o botão azul (Botao_Ingresso). O
BotaoPrincipalController detecta o input, altera a cor do botão via BotaoPrincipalView
e registra a ação no GaleriaManager. As 6 obras no salão principal são para contemplação
— não possuem interação ativa.

6.2 Lógica da Interação (Passos):
1. PlayerController move o XROrigin via WASD com CharacterController
2. Physics.OverlapSphere detecta objetos com tag interativa na zona do player
3. Ao detectar BotaoPrincipalController na zona, o botão muda para estado hover
4. Input.GetKeyDown(KeyCode.E) ou trigger XR → chama BotaoPrincipalController.Ativar()
5. BotaoPrincipalView altera a cor do botão para estado ativo
6. GaleriaManager.Instance?.ExibirMensagem() exibe confirmação no HUD

6.3 Script C# — BotaoPrincipalController.cs (script principal de interação)

using UnityEngine;

public class BotaoPrincipalController : MonoBehaviour
{
    private BotaoPrincipalView view;
    private bool ativado = false;

    private void Awake()
    {
        view = GetComponent<BotaoPrincipalView>();
    }

    public void Ativar()
    {
        if (ativado) return;
        ativado = true;
        view?.SetAtivo(true);
        GaleriaManager.Instance?.ExibirMensagem("Ingresso validado! Bem-vindo ao MetaMuseu.");
    }

    public void AoEntrarHover() => view?.SetHover(true);
    public void AoSairHover()   => view?.SetHover(false);
}

SEÇÃO 9 — REFLEXÃO FINAL

9.1 Aprendizado:
Compreendi na prática como o XR Interaction Toolkit abstrai a complexidade do hardware VR,
permitindo que os mesmos scripts funcionem no Editor (teclado) e no headset (controllers).
A arquitetura MVC foi essencial para manter os scripts organizados e reutilizáveis —
separar ExibitoModel (dados), ExibitoView (visual) e ExibitoController (lógica) tornou
muito mais fácil adicionar novas obras sem modificar código existente.

9.2 Dificuldades Encontradas:
A principal dificuldade foi a ausência de headset para testar a escala real dos objetos —
o XR Device Simulator não representa fielmente as proporções do ambiente em VR. Outra
dificuldade foi a configuração do NDK no Linux (Bazzite), onde symlinks quebrados do
clang++ e lld impediram o build Android e exigiram correção manual. Além disso, o
Meta XR Simulator é exclusivo para Windows e não pôde ser utilizado no ambiente de
desenvolvimento Linux.

9.3 Melhorias Futuras:

  usuários ao museu virtual.
- Adicionar áudio espacial (AudioSource 3D) com narração das obras via AudioClip.
- Criar um sistema de teleporte entre salas para museus maiores.
